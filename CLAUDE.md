# CLAUDE.md — Sepalo

Project-specific instructions for Claude Code. These override any default behaviour.

## Working style

- **Always ask before acting.** Before starting any task — even small ones — confirm the goal, scope, and approach with the user. Do not assume.
- **Keep this file up to date.** When you learn something new about the project (a constraint, a decision, a convention) that isn't already here, propose adding it. Ask first, then update if the user agrees.

## Project overview

Sepalo generates CBI XML payment files (standard `CBIBdyPaymentRequest.00.04.01`) from CSV/XLSX uploads.
All processing is 100% client-side — no payment data ever touches a server.

## Monorepo layout

```
packages/
  core/   — @sepalo/core  TypeScript library: parsers, builders, validators, XSD
  web/    — @sepalo/web   Next.js 15 app (App Router, Tailwind v4, Biome)
```

## Key commands

```bash
pnpm install              # install all workspaces
pnpm dev                  # start Next.js dev server
pnpm lint                 # Biome check (must be 0 errors, 0 warnings before commit)
pnpm typecheck            # tsc --noEmit across all packages
pnpm test                 # vitest (packages/core)
pnpm --filter @sepalo/core build   # rebuild core before web typecheck
```

CI runs: lint → build core → typecheck → test → build. All must pass.

## Git workflow

- **Always** create a branch and open a PR — never commit directly to `main`.
- Branch naming: `feat/`, `fix/`, `chore/`, `docs/`, `refactor/`, `test/`
- Use Conventional Commits: `feat:`, `fix:`, `chore:`, `docs:`, `test:`, `refactor:`
- **Never** add `Co-Authored-By: Claude` or any AI signature to commit messages.
- After merge the maintainer tags `main` manually.

## Do not touch without explicit instruction

- `packages/core/src/data/xsd/` — auto-generated by `embed:xsd` script, never hand-edit
- `packages/web/public/vendor/` — third-party WASM binaries
- `package.json` version fields — managed by Changesets
- `CHANGELOG.md` and `.changeset/` files — managed by Changesets
- Any file not related to the current task

## Testing

Write tests only for non-trivial logic (validators, parsers, builders, crypto utilities).
Simple UI components, wrappers, and configuration files do not need tests.
Tests live in `packages/core/src/` next to the source or under `src/tests/`.

## Core constraints

- **Privacy first**: no payment data may be sent to any server. Tool pages must be 100% client-side.
- **CBI standard**: target format is `CBIBdyPaymentRequest.00.04.01`. Always verify against the official XSD.
  - Outer namespace: `urn:CBI:xsd:CBIBdyPaymentRequest.00.04.01`
  - Inner namespace (`pmrq:`): `urn:CBI:xsd:CBIPaymentRequest.00.04.01`
  - `CBIPaymentRequest` element has no prefix; all its children use `pmrq:` prefix
- **No over-engineering**: three similar lines are better than a premature abstraction.
- **No unsolicited changes**: only modify files that are directly relevant to the requested task.

## Auth & crypto

- Key derivation: PBKDF2 → AES-GCM-256 (Web Crypto API)
- Encrypted storage: idb-keyval with helpers in `packages/web/src/lib/storage.ts`
- Auth constants: `packages/web/src/lib/auth-keys.ts`
- Auth modes: `'pin'` (6-digit) or `'passphrase'` (≥ 12 chars)
